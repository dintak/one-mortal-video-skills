# 端到端工作手冊

本文件是「一個凡人的世界：原創歌曲影片製作」技能的作業細節。服務方案、模型、API、Colab 資源和政策可能更新；每次開工都應核對供應商目前的官方資訊，將即時狀態與本文件中的過往實例分開記錄。

## 1. 接案盤點與素材

### 必需素材

| 素材 | 建議格式／資訊 | 使用方式 |
| --- | --- | --- |
| 原創人聲歌曲 | WAV 優先，MP3 可用；確認取樣率、聲道、實際時長 | 作為最終混音的唯一主音軌 |
| 歌詞 | UTF-8 TXT、DOCX 或貼文 | 校對字幕、提示詞和演唱段落 |
| 歌詞時間軸 | SRT、CSV 或逐句時間碼；標示男／女／合唱 | 決定每段由誰唱、字幕顯示時間和對嘴片段 |
| 角色參考圖 | PNG/JPG；標明角色名稱和使用權 | 鎖定臉、髮型、服裝、性別呈現和配色 |
| 影片規格 | 橫式／直式、解析度、幀率、長寬比、成品長度 | 切段、生成和輸出驗收 |

與使用者確認哪些時間碼是「歌手切換」而非「字幕切換」。例如男聲 01:02–01:14，表示該範圍使用男角色演唱畫面；仍要按歌詞句子或模型可處理的片長再切成短片。合唱段落要明確標成合唱，不能因時間相鄰就自動猜人聲。

只向外部服務傳輸完成該階段所需素材。先讀取而不改寫原始歌曲、歌詞和圖片，另建工作副本。若文件或曲目尚未獲准上傳到指定第三方，就先留在本機或使用者已授權的儲存空間。

### 目錄建議

```text
project/
  input/                  原始音訊、歌詞、時間碼、角色圖（唯讀）
  plan/                   shot_timeline.json、生成規格、模型版本
  clips/                  動態畫面小片段
  lipsync_clips/          對嘴結果
  qa/                     抽格、檢查報告、人工驗收備註
  output/                 最終 MP4、SRT、縮圖、交付說明
  state/                  續跑狀態與工作紀錄
```

實際可按雲端環境調整路徑。若使用 Drive，選定一個明確的根資料夾，例如「我的雲端硬碟／Codex成品／作品名」，所有腳本都以這個根路徑為界。

## 2. 模型與雲端環境選擇

先明確區分下列項目：

1. **模型是否可免費下載／開放權重**：不代表商業授權無限制，也不等於執行影片所需 GPU 免費。
2. **線上生成服務的免費點數**：可能有短片、排隊、浮水印、解析度、每日額度或素材授權限制；開始前在帳號頁核對實際報價與剩餘額度。
3. **Colab 免費 GPU**：GPU 分配、可用時段、執行時長、RAM、GPU 型號都不保證；可能出現等待、閒置中斷、每日／週用量限制或模型重新下載。
4. **Codex Plus**：支付的是 Codex 使用方案，不是影片模型 API、Colab Pro 或 GPU 點數。

每次使用新的模型或工具，開工前記錄：正式名稱、來源 URL、模型版本／commit、授權、所需 VRAM/RAM、雲端用量、輸入素材是否會被第三方保留、輸出能否商用，以及生成時是否計費。以能滿足畫質且符合成本上限的配置為準。優先先做單段端到端 smoke test，再開始長批次。

如果使用 ComfyUI：

- 優先使用官方／維護中的 ComfyUI 安裝文件或已驗證的專案安裝法。
- 隔離安裝目錄和模型快取；除非使用者要求，勿更新其原有 ComfyUI、改動原 workflow、安裝額外 custom nodes 或更改全域套件。
- 記錄 commit、模型檔、服務 port、節點數和 GPU 資訊。只有在基本健康檢查通過後才送第一張工作圖。
- 避免把某次工作記錄中的固定 port、模型或節點版本當成永久規格；每次根據目前 notebook 狀態核實。

## 3. 先做短片品質試映

不要先把整首歌塞進單一生成任務。試映片要代表真實難點，例如：

- 一段男聲、一段女聲或合唱，依歌曲實際分布挑選。
- 角色快速轉頭、張嘴說唱、手勢、衣袖擺動、身體移動及背景動畫。
- 歌詞密集、切換歌手、低光、複雜手部或關鍵道具的段落。

人工逐項確認：

- 臉、髮型、服裝、身材和角色身分有無漂移。
- 手指、手臂、牙齒和嘴部有無生成錯誤。
- 衣袖、身體和背景是否有可見動態，動作是否符合拍點和角色狀態。
- 嘴型是否接近對應人聲；生成模型是否更改、遺漏或添加歌詞。
- 多人鏡頭是否多生／少生人物；鏡頭是否突然切換或漂移。
- 畫面是否帶有模型浮水印、字幕亂碼或未授權品牌。

不合格時只調整最關鍵變數（提示詞、首幀、片長、參考音訊或生成模型）並重跑該短段。先通過試映再擴大批次。

## 4. 長片切段與續跑

### 切段設計

依音訊波形、歌詞停頓、歌手切換、鏡頭主題及模型的實際片長限制建立時間軸。每段記錄：

```json
{
  "id": "S02-01_c01",
  "start": 17.0,
  "end": 22.0,
  "performer": "male",
  "lyric_lines": ["該片段歌詞"],
  "visual_prompt": "該段角色和動作提示",
  "first_frame": "input/characters/male_scene.png",
  "status": "pending",
  "output": "clips/001_S02-01_c01.mp4"
}
```

時間碼以來源歌曲為準。生成片段可因模型所需多留短暫把手，合成前再按時間軸精確裁切或做交疊，避免片段接縫漏拍、重唱或歌詞重疊。

### 每段生成與原子保存

1. 送出一段，保留任務 ID、提交時間、模型／seed、狀態及錯誤訊息。
2. 等生成完成後檢查回應檔完整性。不要把只有檔名、0 bytes 或仍在寫入的影片記成完成。
3. 對輸出使用 ffprobe 核對時長、幀率、畫面尺寸和音軌；用抽格檢查人物及背景連續性。
4. 先寫入同一目標資料夾的暫存檔（例如 `.part.mp4`），全部檢查通過後才原子改名為正式片段名。
5. 更新 `state.json` 或狀態表，保存檔案大小、尺寸、時長和可選 SHA-256；持久儲存位置要確認有同步完成。
6. 每完成數段檢查一次雲端資料夾清單，驗證檔案確實在 Colab 生命週期外仍能取回。

### Colab 中斷復原

Colab runtime 一旦重置，記憶體磁碟、背景程序、GPU 模型快取及正在生成的任務可能消失。不能把 Colab 執行狀態當成保存進度。恢復時依序：

1. 讀最新製作紀錄和狀態檔，重新盤點雲端已保存的片段、大小和可播放性。
2. 將狀態為 `done` 但檔案不存在或檢查失敗的項目降回待處理；保留損毀檔至 `incomplete/`，不要覆蓋上一個有效成品。
3. 確認目前 GPU 型號和可用 VRAM，重建隔離環境；需要重新下載模型時把預計流量和時間記在紀錄裡。
4. 僅從第一個未完成或不完整片段續跑，跳過已驗證片段。
5. 先小批次恢復，核對 Drive 上實際保存結果後再擴大批次。

使用者要求免費工具時，GPU 暫不可用就保存狀態並停止，不買點數、不改用 API，不建立多個帳號來繞過限制。若遇 CAPTCHA 或需重新登入，由使用者親自操作。不要宣稱可以在 Codex 關閉後自行長時間監控；只有平台明確提供並設定的持續執行機制才能這樣說。

## 5. 對嘴和原曲合成

歌曲是唯一的最終人聲來源時，AI 生成片段的音訊需在合成時移除或靜音；不要無意中疊上模型自行生成的歌聲。依歌手時間碼將對嘴處理限定在相應角色片段。多人合唱若模型只能處理單一人聲，可用分開的角色鏡頭交錯剪輯，或保留合唱全景；不可錯把一方的嘴型同步至另一方唱段。

套用 lipsync 前核實：

- 原始影片、對嘴影片與輸入音訊的時間範圍一致。
- 輸出的音訊非空，長度和採樣格式符合工具要求。
- 起訖時間在同一時間基準中；FFmpeg seeking 參數順序要依實際輸入／濾鏡檢查。
- 生成結果沒有意外改變背景、臉型、服裝或片長。

如果工具以多片段方式對嘴，逐段產出並存檔，完成後才合成。先抽查最早、中段和結尾的對嘴片段；合成全片後再逐段抽查歌手切換點和嘴型最大動作處。

## 6. 字幕及最終輸出

從原始歌詞和時間軸建立 SRT。歌詞中標示 `(男)`、`(女)`、`(合)` 之類角色標籤時，先確認是否要在字幕畫面保留標籤。確保：

- SRT 使用 UTF-8，字幕序號連續，時間碼為 `HH:MM:SS,mmm --> HH:MM:SS,mmm`。
- 開始／結束時間不倒置，重疊只在歌詞確實重疊時使用。
- 逐句核對歌詞而不是信任 ASR 或生成模型；文字仍應與原創歌詞相符。
- 字幕不遮住臉、嘴型或重要視覺資訊，行長和停留時間適合閱讀。
- MP4 編碼、畫幅、幀率和音訊格式符合使用者指定的平台。

合成前用 ffprobe 確認音軌、解析度、幀率、總時長；檢查影片開頭、中段、歌手切換、接縫和尾段。播放最終 MP4，不能只檢查檔案已生成。可選再以全片抽格、音訊波形、黑畫面掃描及音訊峰值作輔助驗收。

輸出通常包含：最終 MP4、獨立 SRT、封面圖（若有要求）、短版預覽（若有要求）、README／交付說明、生成模型與版本清單、製作時間和費用紀錄。不要把大型中間模型或暫存檔一起打包給使用者，除非使用者要求。

## 7. 時間、費用與中斷記帳

時間分開寫：

- **總日曆經過時間**：從第一筆可驗證工作紀錄到最終驗收，含排隊、用量重置、使用者驗證、runtime 中斷和等待。
- **已知積極運算時間**：只加總有起訖記錄的模型推論／轉碼時段；缺少記錄就標「無法精確重建」，不可把整段日曆時間當純運算。
- **Codex 工作時間／額度**：只記錄有證據可得的 Codex 使用量或 reset 邊界。不要把每月 Plus 價格當作這支影片的單片成本，除非另行列出是使用者提供的訂閱帳單。

按項目列出實際費用證據：Codex 訂閱（使用者提供或帳單可查）、Colab 方案／運算點數、生成 API 費、第三方工具或儲存、網路／下載費、其他明確支出。未找到付款紀錄時寫「此紀錄未發現額外購買；不代表帳單已全面稽核」。不要根據免費額度推測付費帳單，也不要聲稱雲端完全免費而忽略使用者既有 Pro 訂閱。

一個可用的費用表：

| 項目 | 用途 | 實際支付／方案 | 證據或限制 |
| --- | --- | --- | --- |
| Codex Plus | Agent 協作、腳本整理、監控 | 由使用者提供月費；非 GPU 計費 | 不是單片專屬成本 |
| Colab | GPU 推論與模型執行 | Free／既有 Pro／額外運算單元分開記 | 以帳戶方案或帳單核對 |
| 外部生成 API | 影片／音訊／圖片生成 | 若未使用，列 0 並註明依紀錄 | 不能僅以本機模型推測 |
| Drive／儲存 | 原始素材、檢查點、交付檔案 | 免費容量內或實際方案 | 使用量不等於費用 |

只有 Codex Plus 的免費路線要向使用者說明：模型生成可能不收模型費，但免費 GPU 不保證可取得；可能耗費長時間重新排隊、重建環境和等待額度，因此「工具免費」不等於「快速、不中斷或保證完成」。若 Codex 額度不足，清楚說明哪些工作已保存、何時可由使用者恢復；不要創造虛構的自動續跑承諾。

## 8. YouTube 不公開上傳

只有使用者要求上傳或明確批准後操作。上傳流程：

1. 先確認登入的是使用者指定的頻道，而非僅確認同一 Google 郵箱。
2. 核對 MP4、SRT、標題、說明、兒童專屬設定、AI 合成揭露和封面。
3. 上傳 SRT 作為影片字幕軌，檢查語言與時間碼；成功匯入後回到影片元素畫面確認字幕已附加。
4. 在瀏覽權限選「不公開」，保存後核對平台顯示已發布／已儲存為不公開。若上傳仍轉碼，說清處理中狀態。
5. 交付網址並解釋持連結者可觀看。若使用者要求私人，使用「私人」並設定指定觀看者，不要把「不公開」誤稱私密。
6. 按當前介面要求處理平台條款、AI 揭露或權利聲明；新的法律條款確認須在執行時依適用規則辦理。

YouTube 可能在上傳後繼續轉碼、掃描版權或套用政策。當下沒有警告不代表永久通過或已取得營利權。只描述頁面當時可證明的狀態。

## 10. 本次工作紀錄的歷史案例（不能當成通用保證）

《黑色皮衣亮綠光》原創歌曲影片的本機紀錄顯示：來源歌曲約 141.72 秒，拆成 37 個動態畫面段，另有 19 個獨唱對嘴段；使用隔離的 Colab T4 ComfyUI 工作流製作動態片段，再以 LatentSync 對嘴、FFmpeg 合成原曲和 SRT。最終影片 141.8 秒、848×480 生成素材，另存一份含中文字幕的成片。源紀錄涵蓋免費帳號 GPU 不可用、Pro T4 接手、Colab runtime 重置、模型快取重建、Colab 閒置中斷、手動完成 CAPTCHA、Browser 工具短暫不可用等多次延誤；不是一個常態估時。
